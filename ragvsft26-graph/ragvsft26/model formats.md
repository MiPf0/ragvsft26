- Safetensors
	- ending ".safetensors"
	- estimated distribution 35%
	- "Created by Hugging Face as a safe, fast alternative to PyTorch's pickle-based format. Stores tensors in a simple, memory-mappable binary layout with a JSON header. Key advantage: no arbitrary code execution risk (unlike pickle), extremely fast loading via memory mapping, and supports zero-copy reads. Widely adopted across the Hugging Face ecosystem. Downside: doesn't store optimizer states or training metadata — it's purely for model weights." (generated by Claude Opus 4.6)
- GGUF
	- ending ".gguf"
	- estimated distribution 25%
	- "**GPT-Generated Unified Format** (GGUF) is a file format that streamlines the use and deployment of large language models (LLMs). GGUF is specially designed to store inference models and perform well on consumer-grade computer hardware." ([Source](https://www.ibm.com/think/topics/gguf-versus-ggml#:~:text=GPT%2DGenerated%20Unified%20Format%20(GGUF,on%20consumer%2Dgrade%20computer%20hardware.)))
	- "Successor to GGML, developed by the llama.cpp community. A single-file format designed for CPU and mixed CPU/GPU inference. It's self-contained, embedding metadata (architecture, tokenizer, hyperparameters) directly in the file. Supports various quantization levels (Q2 through Q8, K-quants). Great for local/edge inference on consumer hardware. Downside: primarily tied to the llama.cpp ecosystem, not ideal for training or fine-tuning, and quantized versions lose some accuracy." (generated by Claude Opus 4.6)
- PyTorch
	- endings ".pt", ".pth", ".bin"
	- estimated distribution 20%
	- "**PyTorch (.pt / .pth / .bin)** The default serialization used by PyTorch, based on Python's pickle protocol. Ubiquitous in research and training pipelines. Can store weights, optimizer states, and arbitrary Python objects. Major disadvantage: pickle is inherently unsafe — loading a .pt file can execute arbitrary code, making untrusted files a security risk. Also slower to load than safetensors due to deserialization overhead." (generated by Claude Opus 4.6)
- ONNX
	- endings ".onnx"
	- estimated distribution 3%
	- "**ONNX (Open Neural Network Exchange)** An open interoperability format backed by Microsoft, Meta, and others. Represents models as computation graphs, making them portable across frameworks (PyTorch → TensorFlow → custom runtimes). Optimized via ONNX Runtime for deployment. Advantage: framework-agnostic, wide hardware support (CPU, GPU, NPU, edge devices). Disadvantage: converting large LLMs can be tricky, not all operations map cleanly, and the resulting files can be large. More common for smaller or traditional ML models than for cutting-edge LLMs." (generated by Claude Opus 4.6)
- GGML
	- ending ".bin"
	- estimated distribution 1%
	- "**GGML (GPT-Generated Model Language)** The predecessor to GGUF, also from the llama.cpp project. A flat binary format for quantized inference on CPUs. Largely deprecated in favor of GGUF, which added metadata support and better extensibility. Still found in older model files. Disadvantage: no embedded metadata, so you need external config files; no longer actively developed." (generated by Claude Opus 4.6)
